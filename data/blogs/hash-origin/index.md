# Hash 的诞生：为什么计算机需要哈希？

## 一、Hash 最初要解决什么问题？

**Hash（哈希）在早期计算机中的核心目标，是解决大量数据的快速查找与存储定位问题。**

简单来说：

> 与其逐条搜索数据，不如通过计算，直接知道数据应该存放在哪里。

这就是 Hash 最原始的设计思想。

---

## 二、Hash 诞生之前：数据查找太慢

### 1. 问题背景

假设你是 20 世纪 50 年代的一名程序员。

计算机中存储着 100 万名学生的信息：

| 学号 | 姓名 | 成绩 |
|---|---|---|
| 100001 | Alice | 90 |
| 100002 | Bob | 85 |
| 100003 | Charlie | 95 |
| ... | ... | ... |
| 999999 | David | 88 |

现在需要找到学号为 `837291` 的学生。

### 2. 传统解决方法：顺序查找

最直接的方法是逐条检查：

```python
for student in students:
    if student.id == 837291:
        return student
```

这种方法叫做 **顺序查找（Sequential Search）**。

假设有 100 万条数据：

| 情况 | 查找次数 |
|---|---|
| 最好情况 | 1 次 |
| 平均情况 | 约 50 万次 |
| 最坏情况 | 100 万次 |

时间复杂度：

\[
O(n)
\]

**存在的问题：数据越多，查找通常越慢。**

于是工程师开始思考：

> 能不能不遍历所有数据，而是根据学生编号直接算出数据所在的位置？

这就引出了 Hash 的核心思想。

---

## 三、Hash 的核心创新：把搜索变成计算

### 1. 传统思路

```text
需要查找某条数据
        ↓
从第一条开始搜索
        ↓
逐条比较
        ↓
找到目标数据
```

### 2. Hash 的新思路

```text
需要查找某条数据
        ↓
获取 Key
        ↓
计算 Hash(Key)
        ↓
确定存储位置
        ↓
访问对应位置
```

**核心区别：从逐条寻找，变成通过计算定位。**

### 3. 举个例子

假设我们准备了 1000 个存储位置：

```text
0, 1, 2, 3, ..., 999
```

现在设计一个简单的哈希函数：

```python
def hash_function(student_id):
    return student_id % 1000
```

其中：

- `student_id`：学生编号（Key）
- `%`：取余运算
- `1000`：哈希表容量
- 返回值：计算得到的位置编号

当需要查找学号 `837291` 时：

```python
hash_function(837291)

# 291
```

整个过程：

```text
学号：837291
      ↓
837291 % 1000
      ↓
得到：291
      ↓
访问哈希表位置 291
      ↓
查找目标学生
```

如果该位置存储着目标学生的信息，就能快速找到数据。

### 4. 时间复杂度的变化

| 方法 | 平均查找复杂度 | 100 万条记录 |
|---|---|---|
| 顺序查找 | O(n) | 约 50 万次比较（成功查找且位置均匀时） |
| 二分查找 | O(log n) | 约 20 次比较（数据有序时） |
| 哈希表查找 | O(1) | 平均常数级操作 |

这里的 `O(1)` 指平均情况下的时间复杂度，并不意味着任何情况下都只需要操作一次。

**Hash 的重要价值：在合理设计下，查找效率不会随着数据规模增加而线性下降。**

## 四、Hash 带来了新问题：哈希冲突

Hash 并不是完美的。

考虑刚才的函数：

```python
def hash_function(student_id):
    return student_id % 1000
```

现在有三个学号：

```python
hash_function(837291)  # 291
hash_function(295291)  # 291
hash_function(100291)  # 291
```

虽然三个学号不同，但计算结果完全相同。

```text
837291 ──┐
         │
295291 ──┼──→ Hash → 291
         │
100291 ──┘
```

这种现象叫做：

**哈希冲突（Hash Collision）**

### 为什么冲突不可避免？

假设：

- 可能输入的 Key 有 100 万个。
- 哈希表只有 1000 个位置。

那么一定存在不同 Key 对应同一位置的情况。

这是数学中的 **抽屉原理（Pigeonhole Principle）**。

### 如何解决哈希冲突？

常见方法有两种。

**方法一：链地址法（Separate Chaining）**

同一个位置可以存储多个元素。

```text
Hash(837291) → 291
Hash(295291) → 291
Hash(100291) → 291

位置 291
   ↓
[837291] → [295291] → [100291]
```

查找时先找到位置 291，再检查其中的元素。

**方法二：开放寻址法（Open Addressing）**

如果计算的位置已经被占用，就按照一定规则寻找其他位置。

```text
837291 → 位置 291 ✓

295291 → 位置 291 已占用
       → 位置 292 ✓

100291 → 位置 291 已占用
       → 位置 292 已占用
       → 位置 293 ✓
```

上面展示的是开放寻址中的线性探测法。

## 五、Hash 的历史起源

### 1. 1953 年：早期哈希思想

IBM 工程师 **Hans Peter Luhn** 在 1953 年的一份内部备忘录中，提出了利用计算得到的存储位置组织信息的思想，并讨论了冲突处理。

这被认为是现代哈希技术的重要早期来源之一。

### 2. 1950 年代：独立发展

IBM 的其他工程师也在早期计算机与汇编程序设计中发展出类似的方法。

主要目标包括：

- 根据符号名称快速定位数据。
- 快速进行符号表查找。
- 减少不必要的数据遍历。
- 提高数据存取效率。

### 3. 1956 年：Hash Coding 的公开介绍

Arnold Dumey 于 1956 年在 *Computers and Automation* 发表了关于 Hash Coding 的文章。

其中讨论了利用数学运算将数据 Key 映射到存储位置的思路。

**历史总结：Hash 并非某个人在某一天独立完成的单一发明，而是在 20 世纪 50 年代逐渐发展成熟的一组数据组织与查找技术。**

## 六、Hash 背后的计算机科学思想

Hash 的发展体现了两个重要思想。

### 1. 用计算代替搜索

传统方法：

```text
知道目标 Key
      ↓
搜索数据
      ↓
找到目标位置
```

Hash 方法：

```text
知道目标 Key
      ↓
计算目标位置
      ↓
访问数据
```

本质上就是：

**将查找问题转化为映射计算问题。**

### 2. 空间换时间（Space-Time Tradeoff）

Hash Table 通常需要额外的存储空间。

例如：

```text
1000 个数据
     ↓
可能分配超过 1000 个存储槽位
     ↓
减少冲突
     ↓
提高查找效率
```

这是一种经典的计算机科学思想：

> 使用额外空间，换取更快的运行速度。

当然，空间增加并不保证性能一定提高，具体效果还取决于哈希函数、负载因子以及冲突处理方式。

## 七、Hash 后来发展出了哪些应用？

Hash 最初的重要用途之一是数据定位，但后来逐渐形成不同的应用方向。

| 应用 | 主要目标 | 常见例子 |
|---|---|---|
| Hash Table | 快速查找数据 | Python dict、Java HashMap |
| 数据校验 | 检测内容是否变化 | SHA-256 |
| 密码存储 | 安全验证密码 | Argon2id、scrypt |
| 文件去重 | 识别相同内容 | 内容寻址存储 |
| 版本控制 | 根据内容标识对象 | Git |
| 数据库索引 | 快速定位记录 | Hash Index |

需要注意：

**数据结构中的哈希函数与密码学哈希函数虽然具有共同的映射思想，但设计目标不同。**

- 哈希表强调计算效率、分布均匀和低冲突。
- 密码学哈希强调抗原像、抗第二原像和抗碰撞等安全属性。

### 1. Hash 为什么诞生？

**为了提高数据查找与存储定位的效率。**

最初面临的问题：

```text
数据量越来越大
       ↓
逐条搜索效率低
       ↓
希望直接定位数据
       ↓
设计 Hash 函数
       ↓
Key → Hash → 位置
       ↓
实现快速查找
```

## 最终记忆

> **Hash 最初的重要动机是解决数据快速查找的问题。它的核心思想不是让计算机找得更快，而是通过建立 Key 与存储位置之间的映射，让计算机尽可能不需要逐条寻找。**

**关键词：查找 → 映射 → 定位 → O(1) → 哈希冲突。**
