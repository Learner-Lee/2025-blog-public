# SSH 端口转发指南

在本地浏览器访问远程服务器上运行的服务——不需要 root 权限，不需要修改防火墙。

---

## 原理

SSH 端口转发通过已有的 SSH 连接建立一条加密隧道。浏览器访问本地端口，SSH 悄悄把流量转发到远程服务器。

```
浏览器 → localhost:端口 → SSH 隧道 → 远程服务器:端口
```

---

## 基本命令

在**本地电脑**的终端运行：

```bash
ssh -L <本地端口>:localhost:<远程端口> <用户名>@<服务器地址>
```

**示例**——转发 8102 端口：

```bash
ssh -L 8102:localhost:8102 用户名@服务器地址
```

登录成功后，本地浏览器访问：

```
http://localhost:8102
```

保持这个终端开着，关掉即断开隧道。

---

## 常用参数

| 参数 | 作用 |
|------|------|
| `-N` | 只转发端口，不打开远程 Shell |
| `-f` | 连接成功后自动转入后台运行 |
| `-C` | 压缩流量（网络较慢时有用） |

**后台静默模式**（不占用终端）：

```bash
ssh -NfC -L 8102:localhost:8102 用户名@服务器地址
```

关闭后台隧道：

```bash
pkill -f "ssh -NfC -L 8102"
```

---

## 同时转发多个端口

重复使用 `-L` 即可：

```bash
ssh -L 8102:localhost:8102 \
    -L 8080:localhost:8080 \
    用户名@服务器地址
```

---

## 保存为快捷方式

编辑本地的 `~/.ssh/config`：

```
Host 我的服务器
    HostName 服务器地址
    User 用户名
    LocalForward 8102 localhost:8102
```

之后只需运行：

```bash
ssh 我的服务器
```

隧道会随 SSH 连接自动建立。

---

## 为什么不需要 root

服务器防火墙只能看到 22 端口上的普通 SSH 流量（本来就是开放的）。端口转发发生在 SSH 加密会话内部，服务器上不会新开任何端口，因此不需要防火墙规则，也不需要 `sudo`。

---

## 常见问题

**`bind: Address already in use`** — 本地端口被占用，换一个本地端口：

```bash
ssh -L 9102:localhost:8102 用户名@服务器地址
# 然后访问 http://localhost:9102
```

**`Connection refused`** — 远程服务还没启动，或监听的端口不对，先确认服务已运行。

**隧道空闲后自动断开** — 在 `~/.ssh/config` 里加心跳保活：

```
Host 我的服务器
    ServerAliveInterval 60
    ServerAliveCountMax 3
```
